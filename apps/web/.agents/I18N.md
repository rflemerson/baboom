# Interface translations

- Use Vue I18n in Composition API mode. Initialization is in `src/i18n.ts` and
  registered in `src/main.ts`; component tests register the same plugin.
- `pt-BR` is the default locale (`src/locales/pt-BR.json`); `en-US` is the
  fallback. Both files hold the same keys, which `i18n.spec.ts` checks.
- Numbers, quantities and prices are formatted with `Intl.NumberFormat` in the
  active locale (`src/utils/number.ts`): `R$ 11,52`, `86,7%`, `900,5 g`.
- Use semantic keys through `useI18n().t` in components and `i18n.global.t` in
  helpers. Include accessible names, placeholders and state messages.
- The base resource defines `DefineLocaleMessage` for TypeScript key checking.
  `i18n.spec.ts` checks literal translation references and nonempty base messages.
- Data returned by the API (product names, brands, categories, packaging labels,
  flavors and route instructions) remains domain data, separate from UI messages.
  Payment codes have an explicit UI mapping; unknown codes keep their original text.
- A new locale must translate every key; there is no language switch yet.
- No GNU gettext, PO or MO files are used for frontend translations.
